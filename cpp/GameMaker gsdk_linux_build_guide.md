# PlayFab GSDK C++ -- Linux Build Guide

This document explains how to build the **PlayFab GSDK C++ wrapper** on
Linux using CMake.

------------------------------------------------------------------------

# 1. Project Structure

Your folder should look like this:

    cpp/
    ├─ CMakeLists.txt
    ├─ gsdkWrapper.cpp
    ├─ cppsdk/
    │  ├─ gsdk.cpp
    │  ├─ gsdkConfig.cpp
    │  ├─ gsdkLog.cpp
    │  ├─ gsdkUtils.cpp
    │  ├─ jsoncpp.cpp
    │  ├─ ManualResetEvent.cpp
    │  └─ include/
    ├─ dependencies/
    ├─ build/              (generated by CMake)
    ├─ README.md

Important files:

-   `CMakeLists.txt`
-   `gsdkWrapper.cpp`
-   `cppsdk/`

------------------------------------------------------------------------

# 2. Install Required Tools

Ubuntu / Debian:

    sudo apt update
    sudo apt install -y build-essential cmake

Optional (if curl is required):

    sudo apt install -y libcurl4-openssl-dev

------------------------------------------------------------------------

# 3. Build the Project

Navigate to the project root:

    cd /media/sf_gsdk/cpp

Configure the project:

    cmake -S . -B build -DCMAKE_BUILD_TYPE=Release

Compile:

    cmake --build build -j

------------------------------------------------------------------------

# 4. Expected Output

After compilation the shared library should be generated inside:

    build/

Example output:

    build/libGSDK_CPP_Linux.so

This `.so` file is the Linux shared library for the GSDK wrapper.

------------------------------------------------------------------------

# 5. Common Error: CMakeCache Path Mismatch

Example error:

    CMakeCache.txt directory is different than the directory where it was created

Example paths:

    Current:  /media/sf_gsdk/cpp/build
    Original: /media/sf_Github/gsdk/cpp

This happens because **CMake stores absolute paths inside
`CMakeCache.txt`**. If the project folder is moved or renamed, the cache
becomes invalid.

------------------------------------------------------------------------

# 6. Fix the Cache Error

Delete the old build folder and reconfigure.

    cd /media/sf_gsdk/cpp
    rm -rf build

Then run the build again:

    cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
    cmake --build build -j

------------------------------------------------------------------------

# 7. Alternative Build Method

Another common workflow:

    cd /media/sf_gsdk/cpp
    mkdir build
    cd build
    cmake ..
    make -j

Both methods produce the same result.

------------------------------------------------------------------------

# 8. Clean Rebuild

If you want to rebuild from scratch:

    cd /media/sf_gsdk/cpp
    rm -rf build
    cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
    cmake --build build -j

------------------------------------------------------------------------

# 9. Notes

-   CMake caches build configuration inside `build/CMakeCache.txt`.
-   If the project path changes, always delete the `build` directory.
-   The final output library is used by the server integration.
